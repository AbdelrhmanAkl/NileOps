# لوحة المتابعة (المرحلة 6)

صفحة عربية (من اليمين لليسار) تعرض صورة سريعة للعمليات، وتفتح من المتصفح على `http://127.0.0.1:8000/dashboard`.
**للقراءة والمتابعة فقط**: لا تحتوي أزرار اعتماد أو رفض؛ القرارات تُتخذ من شاشات المراجعة (واجهة `/docs`) بشريًا.

## التشغيل للعرض

```
python -m scripts.init_db
python -m scripts.seed_kyc_data
python -m scripts.seed_banking_data
python -m scripts.load_policies
python -m scripts.create_user          # أنشئ مستخدمًا (مثلًا reviewer)
python -m uvicorn src.api.main:app --reload
```
ثم افتح `/dashboard` وسجّل الدخول. الجلسة 15 دقيقة (إعداد التوكن)، وعند انتهائها تعود الصفحة لشاشة الدخول.

## ما الذي تعرضه

- **نظرة عامة:** عدد العناصر التي تنتظر مراجعة بشرية، الشكاوى العاجلة المفتوحة، حقول OCR التي تحتاج مراجعة، السياسات المعتمدة،
  ثم توزيع الطلبات والمستندات والبطاقات والشكاوى حسب الحالة/الأولوية/التصنيف.
- **قوائم المراجعة:** أول 10 عناصر مفتوحة في كل نوع (الشكاوى مرتبة بالأولوية). زر «شرح الحالة» لطلبات اعرف عميلك والشكاوى
  يفتح الشرح من المرحلة 5 مع السند من السياسات.
- **مساعد السياسات:** سؤال بالعربي؛ إجابة مع المصادر، أو «لا توجد إجابة» عند غياب السند.
- **آخر الأنشطة:** الوقت والعنصر والإجراء والجهة فقط. يتجدد تلقائيًا كل دقيقة وبزر «تحديث».

## الأمان في التصميم

- واجهة `GET /api/v1/dashboard/summary` تعيد **أرقامًا وأرقام مرجعية وحالات فقط**: لا أسماء عملاء، لا وصف شكاوى، لا ملاحظات مراجعين،
  لا قيم OCR، لا نصوص سجل التدقيق ولا أسماء الموظفين. (الاختبارات تزرع بيانات حساسة وتتأكد أنها لا تظهر.)
- الصفحة نفسها لا تحتوي بيانات؛ كل شيء يأتي من الـ API بعد الدخول وبصلاحية المستخدم.
- سياسة CSP صارمة: لا سكربتات ولا أنماط داخل الصفحة، ولا اتصال إلا بنفس الخادم، ولا تضمين في إطارات (`frame-ancestors 'none'`)، مع `no-store` و`nosniff`.
- كل بيانات الخادم تُدرج بـ `textContent` (لا HTML)، فلا يمكن لنص خبيث في قاعدة البيانات أن ينفّذ كودًا في المتصفح. اختبار يمنع استخدام `innerHTML` وأخواتها.
- لا مكتبات خارجية ولا خطوط من الإنترنت: تعمل داخل شبكة مغلقة.
- التوكن يُحفظ في `sessionStorage` للتبويب الحالي فقط (يُمسح بإغلاقه وعند تسجيل الخروج).

## حدود معروفة

- لا يوجد تفاصيل لكل عنصر ولا إجراءات؛ للمتابعة فقط.
- الرسوم أشرطة بسيطة (بدون مكتبة رسوم)، والأرقام تُحسب عند كل فتح؛ مع بيانات كبيرة يلزم تخزين مؤقت.
- لم تُجرَّب الصفحة على متصفحات غير Chromium (جرّبتها آليًا على Chromium بشاشة كمبيوتر وشاشة جوال).
- `sessionStorage` يتأثر بأي ثغرة XSS مستقبلية؛ لذلك الحماية الأساسية هي منع XSS (النقطتان السابقتان). في الإنتاج يُفضَّل
  كوكي `HttpOnly` من الخادم.
