# مساعد السياسات (RAG) مع Qwen المحلي

يجيب الموظف عن أسئلة السياسات **من ملفات السياسات المعتمدة فقط**، ومع كل إجابة مصدرها
(رمز السياسة + الإصدار + القسم). لو السياسات لا تغطي السؤال، **يمتنع** عن الإجابة بدل التخمين.
الإجابة استرشادية والقرار للموظف.

## كيف يعمل (من الأرخص للأغلى)

1. **استرجاع حتمي (BM25 عربي):** تطبيع الحروف، إزالة السوابق/اللواحق، قاموس صغير للعامية
   (`كارت` → `بطاقة`). لا مفاتيح خارجية ولا إنترنت.
2. **نسبة التغطية:** كم من كلمات السؤال المهمة وُجدت في المقطع؟ أقل من **0.55** ⇒ امتناع، ولا يُستدعى أي نموذج.
3. **بدون نموذج (الافتراضي):** يُعرض نص السياسة نفسه مع المصدر.
4. **مع Qwen المحلي:** يعيد الصياغة فقط، ويُقبل ناتجه إذا:
   - كل `[رقم]` يشير إلى مقطع موجود،
   - كل رقم (أرقامًا أو كلمات مثل «واحد») موجود في **المقطع المقتبس في نفس الجملة**،
   - لا يزيد الكلام الغريب عن المقاطع على 40%.
   وإلا يرجع النظام لنص السياسة. وفي **المنطقة الرمادية** (تغطية بين 0.25 و0.55، غالبًا أسئلة بالعامية)
   لا يجيب إلا Qwen وبناتج مُتحقَّق منه؛ ولو لم يتوفر أو رُفض ناتجه ⇒ امتناع.
5. **الخصوصية:** يقبل النظام عناوين خوادم محلية فقط (`localhost` أو شبكة داخلية) — وفق سياسة POL-DPP-001.
   نص السؤال **لا يُسجَّل** في سجل التدقيق (قد يحوي بيانات عميل)؛ يُسجَّل فقط: النتيجة والأسلوب وعدد المصادر.

## تشغيل Qwen على جهازك (Windows)

1. نزّل Ollama من ollama.com وثبّته.
2. في PowerShell: `ollama pull qwen2.5:7b-instruct` (حوالي 5 GB؛ لو جهازك ضعيف جرّب `qwen2.5:3b-instruct`).
3. أضف في ملف `.env`:
   ```
   LLM_PROVIDER=ollama
   LLM_BASE_URL=http://localhost:11434
   LLM_MODEL=qwen2.5:7b-instruct
   ```
4. أعد تشغيل الخادم. للتأكد: `python -m scripts.evaluate_rag --llm`.

بدون هذه الإعدادات يعمل كل شيء بالوضع الافتراضي (بدون نموذج).

## التشغيل

```
python -m scripts.init_db            # ينشئ جداول policy_documents و policy_chunks
python -m scripts.load_policies      # يحمّل knowledge/policies/*.md (آمن للتكرار)
python -m scripts.evaluate_rag       # يقيس الدقة والامتناع
```
أو من الواجهة: `POST /api/v1/policies/reload` (للمدير) ثم `POST /api/v1/policies/ask`.

## إضافة سياسة أو إصدار جديد

ملف Markdown في `knowledge/policies/` بهذا الشكل (الرمز على نمط `POL-XXXX-001`):
```
---
policy_code: POL-CARD-001
version: 3
title: سياسة إصدار البطاقات
department: إدارة البطاقات
effective_date: 2026-06-01
---
## مدة التسليم
...
```
- رقم `version` أكبر ⇒ يصبح هو المعتمد في الإجابات، والقديم يبقى للرجوع إليه.
- تعديل نص إصدار موجود دون رفع `version` ⇒ **تعارض** يُبلَّغ عنه ولا يُطبَّق (حتى لا تتغير إجابة قديمة بصمت).

## النتائج المقاسة (بدون Qwen)

| المجموعة | أجاب بشكل صحيح | إجابات خاطئة | امتناع صحيح خارج النطاق |
|---|---|---|---|
| `eval_questions.json` (26 + 8) | 26 / 26 | 0 | 8 / 8 |
| `eval_questions_dialect.json` (20 + 10) | 10 / 20 | 0 | 10 / 10 |

**اقرأها بحذر:**
- المجموعة الأولى ضُبط القاموس والحدود وهي أمامي، فنتيجتها متفائلة.
- المجموعة الثانية (عامية مصرية) أصعب وأقرب للواقع: **النصف تقريبًا يمتنع**. الامتناع الزائد هو الجانب الآمن،
  لكنه يعني أن النسخة بدون نموذج تحتاج صياغة قريبة من ألفاظ السياسة.
- **لم أجرّب Qwen الحقيقي** (لا يتوفر في بيئة التطوير عندي). اختباراتي تستخدم نموذجًا وهميًا لإثبات أن
  المنطق يرفض الناتج غير المسنود. الأثر الفعلي لـ Qwen على المجموعة الثانية يجب أن تقيسه أنت:
  `python -m scripts.evaluate_rag --llm --questions knowledge/eval_questions_dialect.json`
  وراجع سطرين: «WRONG-POLICY» (يجب أن يبقى 0) و«abstained» خارج النطاق (يجب أن يبقى كاملًا).
  بعض الأسئلة خارج النطاق (مثل «ما رسوم التحويل الدولي؟») تقع في المنطقة الرمادية فتصل للنموذج؛
  لو ظهر أي سؤال منها يُجاب، ارفع `RAG_LLM_MIN_COVERAGE` (مثلًا 0.35) أو عطّل المنطقة الرمادية بجعلها `0.55`.
- قبل أي رقم تقدمه للعميل: اجمع أسئلة موظفيك الحقيقية وأضفها لملف التقييم.

## حدود معروفة

- الاسترجاع معجمي (كلمات) لا دلالي: «ChatGPT» لا يُربط تلقائيًا بـ«خدمة ذكاء اصطناعي خارجية».
  الخطوة التالية الممكنة هي تضمينات محلية (embeddings) بعد قياس الحاجة بأسئلة حقيقية.
- الأرقام المكتوبة بالحروف في ناتج النموذج («سبعة») تُعامل بحذر وقد تجعل النظام يعرض نص السياسة نفسه.
- السياسات الحالية **اصطناعية** وليست سياسات بنك حقيقي.
